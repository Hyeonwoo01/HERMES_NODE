# 현장 검증 계획

목표는 "AI 추천이 정확한가"보다 먼저 **전원 담당자가 기존 방식보다 더 빠르고 안전하게 업무를 마치는가**를 확인하는 것입니다.
모든 단계에서 실제 환자 정보는 쓰지 않고, 실제 진료에 영향을 주지 않습니다.

## 1. 사용성 비교 연구 (모의 케이스, 비개입형)

| 항목 | 내용 |
|---|---|
| 참여자 | 응급실 전원 담당 간호사, 응급의학과 의료진, 상황실 전원 조정 인력 5–10명 (초기 탐색용 — 효과 입증용 표본이 아님) |
| 과제 | 합성 전원 케이스 6건: 뇌졸중·외상·소아 각 1건, 정보 누락 1건, 받을 병원 없음 1건, 1순위 거절 1건 |
| 설계 | 교차 설계. 참여자마다 절반은 기존 방식(종이 양식·전화 스크립트·공공 현황판 화면), 절반은 SYNAPSE-H로 처리하고 순서를 바꿈 |
| 병원 응답 | 진행자가 미리 정한 응답표(수용/거절, 사유)대로 "전화" 응답 — 두 방식 모두 같은 응답표 사용 |
| 기록 | 화면 녹화 + 앱 감사 로그(`synapse_h_audit.jsonl` 다운로드) + 진행자 관찰지 |

### 측정 지표

| 지표 | 정의 | 출처 |
|---|---|---|
| 확정까지 시간 | 케이스 제시 → 수용 병원 확정 (실측) | 관찰지, 감사 로그 `case_opened` → 수용 `contact_outcome` |
| 연락 횟수 | 수용까지 시도한 병원 수 (미해결 포함) | 감사 로그 |
| 정보 누락률 | 수용 병원에 전달한 요약에서 필수 항목이 빠진 비율 | SBAR 요약 vs 정답 체크리스트 |
| 안전 오류 | 역량 없는 병원 선택, 고위험 환자 과도한 원거리 선택, 에스컬레이션 누락 | 독립 검토자 판정 |
| 추천 일치도 | 참여자 선택과 모델 1순위의 일치 (Shadow 모드) | 감사 로그 `recommended_rank` |
| 오버라이드 사유 | 1순위를 따르지 않은 이유 분류 | 감사 로그 |
| 사용성 | SUS 설문, "실제 업무에 쓰겠는가" 5점 척도, 인터뷰 | 설문 |

평균만 보지 않고 **가장 오래 걸린 케이스와 안전 오류**를 따로 검토합니다. 이 연구로 임상 효과를 주장하지 않습니다.

### 진행 순서 (참여자 1명, 약 60분)

1. 동의와 목적 설명, 실제 환자 정보 입력 금지 안내 (5분)
2. 앱 사용법 연습 케이스 1건 (10분)
3. 기존 방식 3건 / SYNAPSE-H 3건 (순서 교차, 30분)
4. 설문과 인터뷰 (15분)

## 2. 현장 문제 크기 확인 (데이터 수집 질문)

사업계획서의 시장 근거는 119 출동·응급실 방문 같은 넓은 숫자입니다. 첫 시장인 **병원 간 전원**의 크기를 직접 확인합니다.

- 목표 지역(또는 참여 병원)의 월간 병원 간 응급 전원 건수와 질환별 비중
- 전원 요청부터 수용 확정까지 걸리는 시간 (중앙값, 오래 걸린 사례)
- 케이스당 연락한 병원 수, 거절 사유 분포 (병상·전문의·장비)
- 정보를 다시 설명해야 했던 횟수, 교대 시 인계 누락 경험
- 현재 쓰는 도구: 공공 현황판, 상황실 요청, 개인 연락망, 메신저
- 병원 상태 정보를 누가, 얼마나 자주 갱신하는지

공식 통계가 없으면 참여 병원에서 2주간 익명 집계표(시간·횟수·사유만, 환자 식별 정보 없음)를 받는 방안을 제안합니다.

## 3. 구매자 인터뷰 (가격·구매 구조 검증)

대상: 지역 응급의료 상황실 담당자, 상급병원 응급실 책임자, 전원 의뢰 병원 관리자, 병원 정보보호·연동 담당자.

1. 이 문제의 예산은 누가 갖고 있습니까? (지자체 / 병원 / 국가 사업)
2. 비슷한 시스템을 도입한 절차와 기간은? (수의계약, 입찰, 시범사업)
3. 연간 지불 가능 범위는? (지역 ₩250M · 고급 노드 ₩60M · 기본 노드 ₩24M 가정에 대한 반응)
4. 보안 심사·EMR 연동 비용은 누가 부담합니까?
5. 내부 개발이나 기존 시스템 확장 대신 외부 제품을 쓸 조건은?
6. 시범사업을 한다면 성공 기준은 무엇입니까?

응답은 "검증된 가정 / 반박된 가정"으로 기록하고, 계약 전에는 매출이나 고객으로 표현하지 않습니다.
