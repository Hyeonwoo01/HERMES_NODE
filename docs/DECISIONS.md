# 기술 의사결정 기록

각 항목은 *무엇을 정했는지 · 왜 · 무엇을 모르는지 · 언제 다시 볼지* 순서입니다.

## D1. 기준 정책은 "가장 가까운 적합 병원"

- **결정:** 디지털 트윈과 동시 배정 비교의 기준선을 *필수 역량을 갖춘 병원 중 이동 시간이 가장 짧은 곳부터 연락*으로 둡니다.
- **이유:** 현장에서 가장 흔하고 설명하기 쉬운 규칙이며, 역량 하드 제약은 두 정책이 똑같이 적용하므로 차이가 순서에서만 생깁니다.
- **모르는 것:** 실제 지역마다 관행(평소 협력 병원 우선, 상황실 지시)이 다를 수 있습니다.
- **다시 볼 때:** 현장 인터뷰에서 실제 연락 순서 규칙을 수집하면 그 규칙을 두 번째 기준선으로 추가합니다.

## D2. 비용 함수와 가중치

- **결정:** `w₁·이동 + w₂·승인지연 + w₃·(1−수용점수)·12분 + w₄·부하·10 + w₅·불확실성·10`, 기본 가중치는 모두 1.0입니다.
  12분은 거절 시 재탐색 비용(실패 연락 6분 × 2), 부하·불확실성의 10은 0–1 값을 분 단위로 환산하는 계수입니다.
- **이유:** 모든 항을 "분"으로 맞춰야 화면의 근거 설명("2순위보다 4.2분 짧음")이 의미를 갖습니다.
- **모르는 것:** 가중치와 환산 계수는 임상·운영 데이터로 보정되지 않았습니다. 가중치에 따라 순위가 바뀔 수 있으며
  (`test_weights_change_ranking`), 이 민감도를 화면에서 직접 조절해 볼 수 있게 했습니다.
- **다시 볼 때:** 파트너 데이터의 실제 연락·수용 시간으로 재탐색 비용과 가중치를 추정합니다.

## D3. 수용 "점수"이지 "확률"이 아님

- **결정:** 화면과 로그에서 `수용 점수 (합성·미검증)`으로 표기하고, 감사 로그 필드명도 `accept_score`로 둡니다.
- **이유:** 로지스틱 함수가 0–1 값을 내더라도 계수가 합성이므로 실제 수용 빈도와 맞는다는 근거가 없습니다. 구간과
  신뢰도 라벨도 피드 신선도·부하로 만든 규칙 기반 표시이며 실측 불확실성이 아닙니다.
- **다시 볼 때:** 실제 데이터로 Brier score, log loss, 보정 곡선, 예측 구간 포함률, 병원·질환별 성능을 보고한 뒤에만
  "확률"이라는 표현을 씁니다 (TRIPOD+AI).

## D4. 언제 추천을 멈추고 사람에게 넘기는가

| 조건 | 동작 | 코드 |
|---|---|---|
| 필수 필드 누락·범위 밖, 부정·과거력으로 경로 근거 소실, 경로 충돌, 불명확한 발병 시각 | 추천 실행 안 함, 해당 항목 입력 요구 | `intake.py` |
| 필수 역량·병상을 갖춘 병원 없음 | 의료지도 에스컬레이션 | `optimizer.py` `no_eligible` |
| 피드 60분 초과 | 해당 병원 제외 (전화 확인 필요) | `eligibility()` |
| 1순위 신뢰도 낮음 | 순위는 참고용, 의료지도 확인 권고 | `low_confidence` |
| Pre-KTAS ≤ 2인데 1순위가 가장 가까운 적합 병원보다 10분 초과 멂 | 의료지도 확인으로 에스컬레이션 | `travel_guardrail` |

- **모르는 것:** 10분, KTAS ≤ 2, 15/60분 신선도 기준은 공학적 placeholder입니다. 임상 안전 책임자가 경로별(예: 뇌졸중
  재관류 시간창, 외상 골든타임)로 정의해야 하며, `optimizer.SAFETY_RULES`에 모아 두어 바꾸기 쉽게 했습니다.

## D5. 디지털 트윈이 알 수 있는 것과 없는 것

- **결정:** 정책의 예측기는 앱이 실제로 관찰할 수 있는 정보(과거 수용률, 보고된 부하 — 오래된 피드는 더 부정확)만
  앱과 같은 기준식으로 씁니다. 실제 수용을 결정하는 잠재 값, 지역 혼잡 충격, 설명되지 않는 변동은 보지 못합니다.
- **이유:** 이전 버전은 "실제 잠재 값 + 잡음"을 예측값으로 써서 실제보다 유리한 결과가 나올 위험이 있었습니다.
- **모르는 것:** 합성 세계 자체가 실제 병원 행태와 다를 수 있습니다. 신뢰구간은 난수 변동만 반영합니다.
  관찰 불가 변동을 키우면 이득이 줄어드는 것을 테스트로 확인합니다 (`test_twin_gain_shrinks_when_acceptance_is_less_observable`).
- **다시 볼 때:** 파트너 데이터로 합성 분포를 한 요소씩 교체하고, 바뀐 결과를 `results/`에 남깁니다.

## D6. 규칙 기반 추출기를 기본값으로

- **결정:** LLM 대신 정규표현식·키워드 규칙을 기본 추출기로 두고, `Extractor` 프로토콜로 교체 가능하게 했습니다.
- **이유:** 오프라인에서 재현 가능하고, 실패가 예측 가능하며, 소비자용 LLM에 건강정보를 보내지 않는다는 원칙을 지킵니다.
- **모르는 것:** 표현 다양성(오타, 약어, 혼합 언어)에 약합니다. 그래서 모든 값은 의료진 확인을 거칩니다.

## D7. 감사 지표 정의

- **첫 통화 수용률:** 연락한 케이스 중 처음 연락한 병원이 수용한 비율 (어느 순위를 먼저 골랐든).
- **모델 1순위 수용률:** 모델 1순위에 먼저 연락한 케이스만 대상으로 한 수용 비율. 위의 값과 섞지 않습니다.
- **케이스당 연락:** 끝내 수용되지 않은 케이스도 포함합니다.
- **수용까지 시간:** 의료진 확인 시각부터 수용 기록 시각까지 *실측*. 3분/6분 규칙으로 계산한 값은 "가정 기준"으로 따로 표시합니다.
