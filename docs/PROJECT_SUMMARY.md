# SYNAPSE-H 프로젝트 요약

**병원 간 응급 전원에서 "어느 병원에 먼저 연락할지"를 정리해 주는 사람 감독형 의사결정 지원 프로토타입**
Hyeonwoo An · 개인 프로젝트 · 2026 · [웹 앱](https://hermesnode.streamlit.app/) · [모바일 앱](https://synapse-h-mobile.streamlit.app/) · [저장소](https://github.com/Hyeonwoo01/HERMES_NODE)

> 합성 데이터 프로토타입입니다. 병원·환자·수용 점수는 가상 예시이며 실제 병원 데이터로 검증되지 않았습니다.

## 1. 문제

전원이 필요하다고 판단된 중증 환자를 받을 상급병원을 찾는 일은 대부분 순차 전화 탐색입니다. 국가응급의료상황실의
2017–2019년 전원 조정 요청 10,222건을 분석한 연구에서 요청 사유는 의료인력 부족(59.8%)과 중환자실 병상 부족(30.8%)이
대부분이었고, 지연은 병원 자원 부족과 연관되었습니다 (BMC Emergency Medicine 2023).

공공 응급자원 현황판은 *지금 무엇이 보고되었는지*를 보여 주지만, 전원 담당자가 답해야 하는 질문은 다릅니다.
**"이 환자에게, 지금의 불확실성 아래서, 어느 병원부터 연락해야 하고 그 이유는 무엇인가?"**
이 프로젝트는 정보 정리와 연락 순서에서 생기는 지연을 다룹니다. 병상·인력 부족 자체는 해결하지 못합니다.

## 2. 해결 방식

| 단계 | 하는 일 | 안전장치 |
|---|---|---|
| 입력 | 의뢰 메모 또는 항목별 입력 | 실제 환자 정보 입력 금지 안내 |
| 확인 | 메모에서 나이·활력징후·KTAS·발병 시각·임상 경로를 추출하고 근거 원문을 표시 | 의료진이 확인해야만 다음 단계로 감. 부정 표현·과거력·경로 충돌·단위 오류는 사람에게 물음 |
| 매칭 | 필요한 진료 역량·병상·피드 신선도로 후보를 거른 뒤, 이동·승인 지연·거절 위험·부하·불확실성 비용으로 순위 | 역량이 없으면 거리와 무관하게 제외 |
| 결정 | 설명 가능한 Top 3와 "1순위인 이유" 표시, 사람이 선택 | 1순위가 아니면 사유 필수. 받을 병원이 없거나 고위험 환자를 과도하게 먼 곳으로 보내면 의료지도로 에스컬레이션 |
| 기록 | 통화 결과(수용·거절) 기록, 거절 시 재추천, 전원 의뢰 요약(SBAR) 생성 | 모든 추천·선택·사유·시각을 감사 로그로 남김 |

동시에 여러 환자가 발생하면 병원을 병상 슬롯으로 펼쳐 헝가리안 알고리즘으로 전체 비용이 최소인 배정을 찾습니다.
같은 병원에 몰릴수록 벌점을 주고, 중증 환자의 지연을 더 무겁게 계산합니다.

## 4. 검증 결과 (합성 데이터)

디지털 트윈: 같은 합성 수용 결과를 공유하는 짝지은 에피소드 2만 건에서 "가장 가까운 적합 병원부터 연락" 정책과
비교했습니다. Synapse-H 정책은 앱이 실제로 관찰할 수 있는 정보(과거 수용률, 오래될 수 있는 보고 부하)만 사용합니다.

| 지표 | 가장 가까운 병원 | Synapse-H | 차이 (seed 10개, 95% CI) |
|---|---|---|---|
| 1순위 수용률 | 64.1% | 69.9% | +5.5%p [+5.3, +5.7] |
| 평균 승인 시간 | 6.77분 | 6.31분 | −0.45분 [−0.46, −0.43] |
| 평균 이송 시간 | 16.50분 | 16.82분 | +0.31분 |

거절 위험을 줄이는 대신 이송 시간이 조금 늘어나는 교환 관계입니다. 관찰할 수 없는 변동을 키우면 이득이 줄어드는 것도
테스트로 확인했습니다. `python scripts/run_twin_experiment.py`로 같은 결과가 재현됩니다.

**이 결과가 말하지 않는 것:** 사망률·임상 효과·실제 병원 행태. 신뢰구간은 시뮬레이션 난수 변동만 반영합니다.

## 5. 기술적으로 고민한 지점

- **확률이라고 부르지 않기:** 로지스틱 함수가 0–1 값을 내도 계수가 합성이므로 "수용 점수(미검증)"로 표기합니다. 실제 데이터가
  생기면 Brier score, 보정 곡선, 예측 구간 포함률로 검증한 뒤에야 확률이라는 표현을 씁니다.
- **시뮬레이션의 정보 누수 제거:** 초기 버전은 예측기가 실제 잠재 수용 값에 잡음만 더해 결과가 과장될 수 있었습니다.
  관찰 가능한 입력만 쓰도록 고치자 개선폭이 +6.3%p에서 +5.5%p로 줄었습니다.
- **지표를 섞지 않기:** "첫 통화 수용률"과 "모델 1순위 수용률", 기록 시각으로 잰 실측 시간과 가정 시간을 분리하고,
  수용되지 않은 케이스도 지표에 포함합니다.
- **사람에게 넘기는 조건을 명시:** 추천을 멈추는 조건을 코드 한 곳에 모으고 테스트했습니다. 임계값은 임상 검토 전 임시값입니다.

## 6. 사업 측면 요약

첫 시장은 병원 간 응급 전원(지역 상황실 + 응급의료기관 414곳). 반복 매출 TAM ₩20.7B는 경영진 가격 가정입니다.
사업계획을 코드로 다시 계산해 보니 첫해 요청 자금 ₩70M으로는 2년 차까지의 누적 손실을 메우지 못해 최소 ₩350M의 추가
조달이 필요하고, 공공기관 대금 회수가 늦으면 운전자본 부담이 더 커집니다. 수정안은 사업계획서 v2에 반영했습니다.

## 7. 한계와 다음 단계

1. **현장 사용성 비교:** 전원 담당자 5–10명이 모의 케이스를 기존 방식과 이 도구로 각각 처리해 확정 시간·연락 횟수·정보 누락·
   안전 오류를 비교합니다 ([검증 계획](VALIDATION_PLAN.md)).
2. **문제 크기 확인:** 목표 지역의 월간 전원 건수, 확정까지 시간, 거절 사유를 익명 집계로 수집합니다.
3. **공공 데이터 연동:** 응급의료기관 정보 OpenAPI를 연결하고 출처·갱신 시각을 그대로 보여 줍니다.
4. **실제 데이터 검증:** 파트너 데이터와 법적 근거가 생기면 수용 점수를 재학습·보정하고 섀도 모드로 평가합니다.
5. **LLM 추출기:** 추출기를 바꿔 끼우는 구조에 Claude·GPT 추출기를 붙이고, 근거 원문 검증과 규칙 기반 대체를 넣은 뒤
   합성 메모로 정확도를 비교합니다.

## 8. 역할 분담과 주요 판단

- **직접 한 일:** 문제 정의, 사업계획서, 요구사항, 설계 결정, 검증 기준, 결과 검토
- **AI 코딩 도구(Claude Code)에 맡긴 일:** 코드 구현 (자동 테스트 29개 + CI로 확인)
- **주요 판단:**
  - 모바일 앱에서 빠졌던 의료진 확인 단계를 안전 원칙에 따라 되살림
  - 외부 검토를 받아 지표 정의와 시뮬레이션의 정보 누수를 바로잡음 (성능 수치가 +6.3%p → +5.5%p로 낮아져도 재현 가능한 수치를 택함)
  - 실제 데이터 없이 "확률"이라고 부르지 않기로 함
  - 고위험 환자의 원거리 배정을 의료지도 확인으로 넘기도록 안전 규칙 강화
