# 규제 분류 자가 점검 (초안)

> **이 문서는 분류 결정이 아닙니다.** SYNAPSE-H가 의료기기(디지털의료기기 소프트웨어)에 해당하는지, 해당한다면 어떤 등급인지는
> 식품의약품안전처가 판단합니다. 이 문서는 사전 상담을 준비하려고 기능별로 쟁점과 현재 설계를 정리한 것입니다.
> 법령·가이드라인 날짜는 [사업계획서 수정 내역](PROPOSAL_REVISIONS.md)의 "규제·표준 최신화" 절에서 확인한 내용만 적었습니다.

## 1. 의도된 용도 (초안 문장)

> 병원 간 응급 전원 업무에서, 권한 있는 의료진이 확인한 환자 정보와 병원의 병상·진료 역량 정보를 바탕으로
> **연락할 병원의 후보와 순서를 제안**하는 소프트웨어. 진단·치료 방법을 제시하지 않으며, 최종 목적지 선택과
> 연락은 의료진이 한다.

이 문장을 어떻게 쓰느냐가 판단에 가장 큰 영향을 줍니다. 범위를 넓히는 표현(예: "최적 치료 병원 결정", "생존율 향상")은 쓰지 않습니다.

## 2. 기능별 쟁점

| 기능 | 판단에 영향을 줄 수 있는 점 | 현재 설계 |
|---|---|---|
| 환자별 목적지 순위 제안 | 환자의 활력징후·Pre-KTAS·임상 경로를 입력받아 **환자별로** 결과가 달라짐 | Top 3와 근거를 모두 표시, 사람이 선택, 1순위가 아니면 사유 기록 |
| 필수 진료 역량 제약 | 임상 경로별 필요 역량 규칙이 추천 결과를 좌우함 | 규칙을 코드 한 곳(`capabilities.py`)에 두고 화면에 표시, 임상 검토 전 임시값 |
| 의뢰 메모 구조화 추출 (규칙 기반 · 선택적 LLM) | 자유 텍스트에서 임상 값을 읽음 | 근거 원문 표시, 범위 검사, 의료진 확인 없이는 순위 계산 불가, LLM 값은 원문·규칙 교차 확인 |
| 수용 점수 | 병원 수용 가능성 예측 (임상 결과 예측이 아님) | "수용 점수(미검증)"로 표기, 확률이라고 부르지 않음, 보정 파이프라인 준비 |
| 고위험 환자 이동 가드레일·에스컬레이션 | 안전 규칙이 추천을 멈춤 | 의료지도 확인으로 넘김, 임계값은 임상 검토 전 임시값 |
| 병원 병상·역량 현황 표시 | 공공데이터 집계·표시 | 출처·갱신 시각·가정값 표시, 오래된 정보는 제외 |
| 전원 의뢰 요약(SBAR)·FHIR 내보내기 | 확인된 값의 전달 | 의료진이 확인한 값만 사용 |

## 3. 관련 법령·가이드라인 (확인한 범위)

- 디지털의료제품법 (법률 제20139호, 2025.1.24 시행)
- 디지털의료기기 변경관리 계획서 허가·심사 가이드라인 (2026.6.26 제정) — 수용 점수 재학습 같은 계획된 변경과 관련
- 허가·심사 규정 개정 (고시 제2026-54호, 2026.7.27 시행) — 소프트웨어 임상시험 자료 면제·간주 기준
- 전문가용 디지털의료기기 소프트웨어 가이드라인 (2026.9.30 제정) — 의료인의 진단·지시·감독 아래 **환자가 쓰는** 소프트웨어 대상.
  SYNAPSE-H는 의료진이 직접 쓰므로 직접 대상은 아니지만, 사용 목적과 경고 문구를 정하는 방식에 참고합니다.

제출 전에는 국가법령정보센터와 식약처 누리집 원문을 다시 확인합니다.

## 4. 사전 상담에서 물을 질문

1. 환자별 정보를 입력받아 **연락 순서만** 제안하고 최종 선택은 의료진이 하는 소프트웨어가 의료기기에 해당하는지
2. 해당한다면, 의도된 용도 문장을 어떻게 쓰면 범위가 명확해지는지 (전원 조정 업무 지원 vs 진료 결정 지원)
3. 의뢰 메모 자동 추출(특히 LLM)을 포함하면 판단이 달라지는지, 의료진 확인 단계가 어떻게 평가되는지
4. 수용 점수를 실제 데이터로 재학습할 때 변경관리 계획서로 다룰 수 있는 범위
5. 섀도 모드(추천을 숨기고 실제 선택과 비교) 평가가 임상시험에 해당하는지, 어떤 절차가 필요한지
